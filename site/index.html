Dwaar (द्वार) is a fast, keyboard-driven TUI for managing SSH and local port forwards. Create rules, start and stop tunnels, and watch live traffic — without re-typing a single ssh -L flag.

Install Dwaar See it in action
build & run 
git clone https://github.com/omangm/dwaar
cd dwaar
go build -o dwaar ./cmd/dwaar
./dwaar

Features

Tunnels without the tab-juggling

Everything you need to keep a fleet of forwards straight, in one screen you can drive entirely from the keyboard.

Keyboard-first rule manager

Add, edit, and delete forwarding rules in a built-in form — local port, remote host and port, SSH hop, and autostart toggles included.

One-key tunnel control

Highlight a rule and hit space. Dwaar opens the listener, forwards traffic, and tears it down just as fast.

Status at a glance

running stopped error are surfaced inline, so a dead tunnel never hides in a scrollback.

Live traffic stats

Per-tunnel sent and received byte counters tick up while a tunnel runs — proof that bytes are actually moving.

Persistent YAML config

Rules are saved to ~/.config/dwaar/rules.yaml with user-only 0600 permissions, and loaded again on the next run.

SSH hops, key or password

Forward through a bastion with an identity file or a password. Local forwards work too — no SSH required.

How it works

Three steps, then it stays out of the way

  1. 1

    Define a rule

    Describe the mapping once: local port → remote host:port, optionally through an SSH hop, with autostart if you always want it up.

  2. 2

    Press space

    Dwaar binds the local port and pipes traffic to the target. Press space again to stop it.

  3. 3

    Watch it run

    Follow a single tunnel with l or everything with g, and read live byte counters in the list.

Configuration

Plain YAML, yours to keep

Rules persist automatically. Edit the file by hand to import or bulk-modify forwards — the TUI picks up the changes on the next launch.

  • Stored at ~/.config/dwaar/rules.yaml
  • Written with user-only 0600 permissions
  • auto_start brings up tunnels on launch
  • Optional via block attaches an SSH bastion
Heads up: an SSH password in the config is stored in plaintext, protected only by file permissions. Prefer key-based authentication.
~/.config/dwaar/rules.yaml 
version: 1
rules:
  - id: rule_1
    name: db-direct
    local_port: 5432
    remote_host: 10.0.0.5
    remote_port: 5432
    protocol: tcp
    auto_start: true
  - id: rule_2
    name: redis-via-bastion
    local_port: 6379
    remote_host: 10.0.0.6
    remote_port: 6379
    protocol: tcp
    auto_start: false
    via:
      host: bastion.example.com
      port: 22
      user: deploy
      identity_file: ~/.ssh/id_ed25519
      # password: hunter2  # alternative to identity_file

Questions

Good to know

Do I need an SSH server for local forwards?

No. If a rule has no via block, Dwaar binds the local port and forwards straight to the remote host:port.

How are my rules saved?

Automatically to ~/.config/dwaar/rules.yaml. The directory is created with 0700 and the file with 0600 permissions.

Can I start tunnels when Dwaar launches?

Yes — set auto_start: true on a rule (or flip the toggle in the form) and Dwaar brings it up on startup. Failures show up as an error status.

Which protocols are supported?

Rules carry a protocol field; the built-in form currently creates TCP forwards.

Does it work over a slow terminal?

Dwaar renders with Bubble Tea and refreshes counters once per second, so it stays responsive over SSH and in tmux.
